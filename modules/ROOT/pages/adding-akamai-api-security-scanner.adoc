= Adding a Scanner for Akamai API Security
ifndef::env-site,env-github[]
include::_attributes.adoc[]
endif::[]

Add a scanner to correlate security findings from Akamai API Security with services that already exist in Exchange. Use the findings to triage risk, track incidents, and remediate vulnerabilities in one governance workflow.

Unlike other scanners, the Akamai API Security scanner doesn't discover or import services. It pulls security findings and incidents from Akamai API Security on the schedule you set and then correlates them with your existing APIs and MCP servers. For Akamai to attribute findings to your APIs, the Akamai correlation policy must be applied to your API instances. The policy stamps correlation headers on API responses.

== Before You Begin

Before adding the scanner, verify that you have these prerequisites:

* Exchange Administrator permission
* Akamai API Security base URL, for example, `https://<tenant>.nonamesec.com`
* Client ID and client secret of an Akamai API Security service account
+
You must have access to create service accounts in Akamai API Security. For more information, see the Akamai API Security documentation.
* Access to apply the Akamai correlation policy in the environments you want to scan
* Existing APIs and MCP servers that serve as correlation targets for the findings
* A connected app in Anypoint Platform that Akamai uses to read API asset and instance information
+
Create a connected app that acts on its own behalf (client credentials) and has the *Exchange Viewer* or *Asset Viewer* scope. Then enter the connected app's client ID and client secret in your Akamai API Security tenant. For more information, see xref:access-management::creating-connected-apps-dev.adoc[].

For more information about tenant connectivity, see xref:general::exp-akamai-risk-correlation.adoc[Correlating Risk Using Akamai API Security].

== Add a Scanner for Akamai API Security

. Verify that you are in the business group where you want to add the scanner.
. From the sidebar in Exchange, click *Scanners*.
. Enter a name for the scanner.
. From *Scanner Run Configuration*, complete these fields or options:
+
[%header,cols="1,4"]
|===
|*Field/Option* |*Value*
|*Run Schedule* |Select a frequency and local time.
|===

. From *Connection Configuration*, complete these fields:
+
[%header,cols="1,4"]
|===
|*Field* |*Value*
|*Provider* |Select *Akamai*.
|*Platform* |Select *Akamai API Security*.
|*Service Type* |*SECURITY_REPORT* selected by default.
|*Authentication Method* |*OAuth* selected by default.
|*Base URL* |Enter the base URL of your Akamai API Security tenant. For example, `https://your-tenant.nonamesec.com`.
|*Client ID* |Enter the client ID of the Akamai API Security service account.
|*Client Secret* |Enter the client secret of the Akamai API Security service account.
|===

. Click *Test Connection*.
+
If the connection fails, review the *Connection Configuration* settings. Update the settings, and then test the connection again.
. To send email notifications:
+
.. Select *Advanced Settings* and turn on *Send Email Notifications*.
.. Enter an email address.
. Click *Add Scanner*.

== Akamai Correlation Policy

Akamai can attribute findings only to API instances that have the Akamai correlation policy applied. Apply the policy in each environment that you want to scan. Akamai observes traffic only for domains that you own and control.

For more information about the correlation policy, reviewing findings, and troubleshooting missing results, see xref:general::exp-akamai-risk-correlation.adoc[Correlating Risk Using Akamai API Security].
